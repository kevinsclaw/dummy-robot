# 为什么手眼标定需要深度信息？没有深度只能做 2D 平面标定

> 记录单目 RGB 手眼标定的核心假设：为什么 9 个标定点的 Z 必须保持不变。

## TL;DR

当前 `calibrate.py` 用的是 **2D 平面标定**（单目 RGB + 仿射变换）。
它要求所有标定点都在**同一个固定高度的平面**上（Z = 常数），
因为单目相机没有深度信息，只有在"目标位于已知平面"的前提下，
才能从一个像素 `(u, v)` 唯一反推出机械臂的 `(x, y)`。

要做真正的 3D 标定（目标可以在任意高度），就**必须引入深度信息**
（深度相机 / 双目 / 结构光等）。

---

## 1. 仿射变换只能解 2D → 2D 的映射

标定计算的是这个 2×3 仿射矩阵：

```
[x]   [a  b  tx] [u]
[y] = [c  d  ty] [v]
                 [1]
```

- **输入**：像素坐标 `(u, v)` —— 2 个量
- **输出**：机械臂平面坐标 `(x, y)` —— 2 个量

整个数学模型里**根本没有 Z**。它本质上假设：
"像素坐标 → 桌面上某个固定高度的 (x, y) 平面坐标"。

## 2. 单目相机没有深度信息

一个像素点 `(u, v)` 对应的不是空间中一个点，而是相机射出的**一整条光线**。
这条光线上的无数个 3D 点都会投影到同一个像素。

要从单个像素确定唯一的 `(x, y)`，**必须假设目标落在一个已知的固定平面上**
（即 Z = 常数）。这样光线与该平面的交点才是唯一的。

如果标定时各点 Z 不同，那么同一个机械臂 `(x, y)` 在不同高度会投影到**不同像素**，
映射关系不再唯一，仿射矩阵根本拟合不出来（或拟合出来误差极大）。

## 3. 所以 9 个标定点必须共面（同一 Z）

- **标定阶段**：标记物（小黄鱼）都在 `calib-z` 这个平面上采点
  → 建立"该平面像素 ↔ 机械臂 (x, y)"的对应关系。
- **使用阶段**：目标（积木）放在桌面上（固定高度 `grab-z`），
  相机看到目标像素 → 用矩阵反推 `(x, y)` → 机械臂下到 `grab-z` 去抓。

## 4. 这个方案的代价与适用范围

- 只对**一个特定高度的平面**有效。
- 目标物必须都在同一桌面高度上。
- 如果目标有高有低（堆叠、不同厚度），平面标定就会有偏差。

要处理任意高度的目标，才需要 **3D 标定 + 深度信息**。

### 注意：`calib-z` 与 `grab-z` 最好一致

当前默认 `calib-z=220`（标定高度）、`grab-z=150`（抓取高度）并不相同。
理想情况两者应一致——标定平面和抓取平面不同高度时会引入**视差误差**。
（不过该误差通常远小于识别不稳定造成的误差，先保证识别准确再优化此项。）

---

## 5. 项目背景：为什么我们现在用 2D 方案

- 原计划用 Orbbec Gemini 2 深度相机做 3D 标定。
- 该 OEM 深度模组（PID 0x0614）因 SDK 发送未文档化 vendor command（opcode 0x000E）
  导致 depth 芯片固件被写坏（brick），USB PHY 无法枚举，深度功能彻底失效。
- 仅 RGB 模组（独立芯片）正常。
- 因此退而采用 **RGB 单目 + 仿射变换的 2D 平面标定**作为合理折中。

> 详见 `memory/2026-06-13.md` 中的 Orbbec 深度相机故障记录。
